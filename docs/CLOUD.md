# クラウド構成の検討

このファイルは設計説明。AWS実配備・IaCの実行・運用・費用試算の証拠ではない。

想定構成は、HTTPSのALBからプライベートサブネットのECSサービスへ接続し、RDS PostgreSQLを利用する。入力CSV・処理状態はDBに保存されるため、アプリ再起動後もキューを回復できる。アプリを複数起動した場合もワーカーはDBで取得対象を分離する。

本番化には次を別途実装・検証する。

- 固定デモキーを廃止し、OIDC・利用者/組織・役割の管理を用意する。
- タスクの権限を最小化し、Secrets Managerから実行時にDB認証を供給する。イメージやGitへ保存しない。
- RDSへのアクセスはアプリ用セキュリティグループのみ。TLS接続・証明書検証、移行用と実行用DBユーザーを分離。
- マイグレーションをアプリ起動からリリース工程へ分ける。
- 組織別キュー上限、リース期限、ワーカー数、DB接続枠は負荷とテナント公平性を測定して設計する。
- 保存期限、監査保全、バックアップと復旧訓練、CloudWatchの失敗・期限切れ・DB待機の通知を設計する。
- 公開ネットワークでのレート制限、WAF、ログの秘匿・削除、PIIの扱いを整える。

KafkaやSQSを導入する場合は、DBと外部キューの送信原子性、Outbox等による再配信、消費者の重複防止を改めて設計する。現在のDBキューを、そのまま外部メッセージングの実装経験としない。
